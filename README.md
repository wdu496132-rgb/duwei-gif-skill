# 万能 GIF 工坊 · Universal GIF Studio

输入角色、动漫或游戏名，把招牌动作做成可以单独发送的循环动图。项目提供 **Agent Skill** 和 **本地导出脚本**，支持单角色多动作、多角色主题包，以及小红书竖版九宫格展示。

## 一句话开始

在支持 Agent Skills 和图像生成的助手中导入本项目。入口是 [SKILL.md](SKILL.md)，导入时保留整个目录。然后可以直接输入：

| 输入示例 | 会得到什么 |
| --- | --- |
| `胡桃` | 胡桃的 9 张不同动作 GIF，例如招来小幽灵、探头和挥手 |
| `火影忍者` | 9 位代表角色的招牌动作，每人一张 |
| `王者荣耀，只要李白、貂蝉和曜，各做一张` | 指定的 3 张动作 GIF |
| `用我上传的角色图，做挥手、转身、比心，像素风` | 沿用角色外观的 3 张自定义动作 GIF |
| `把这 9 张动图做成小红书九宫格` | 1080×1920 竖版 MP4，九个动作同屏播放 |

直接报名字时可先唤起 `$universal-gif-studio`，让助手知道这次要做动图。角色重名时加上作品名或参考图。想精确控制结果，可以一起指定**数量、动作、风格、尺寸、底色和时长**。

> 用万能 GIF 工坊给胡桃做 3 张。动作是招来小幽灵、偷偷探头、笑着挥手。Q 版，透明底，每张节奏跟着动作走，最后打包成 ZIP。

## 成品规格

| 项目 | 默认值 |
| --- | --- |
| 角色包 | 9 张独立 GIF，每人或每个动作一张，打包为 ZIP |
| 单张动图 | 512×512，64 帧，透明底，无文字，循环播放 |
| 动作节奏 | 按动作安排。快动作通常约 1.9 秒，复杂动作约 2.3 至 2.6 秒 |
| 九宫格视频 | 默认随包交付。3×3 同屏，九格全部展示角色 GIF，无空格；浅色实底、1080×1920、60 FPS、H.264 MP4，默认 8 秒 |

### 动作是怎么做出来的

1. **设计动作**。根据角色的姿势、表情和道具，安排准备、发力、高潮和收势。
2. **绘制关键姿势**。图像生成助手把 16 个关键姿势放在一张 4×4 动作图里，保持角色比例、镜头和脚底位置一致。
3. **补过渡并导出**。本地脚本把 16 张关键姿势转换成 64 个画面，并在最后一张与第一张之间补过渡。
4. **检查成品**。脚本校验帧数、透明度、时长和循环标记。播放时还需检查手脚、道具、出招与收势。姿势跨度太大时，通常要补画中间姿势才能避免重影。

新角色和新动作的绘制需要助手具备图像生成能力。已有动作图或符合要求的源 GIF 时，可以直接使用下面的脚本。

## 本地导出 GIF

需要 Python 3.10 或更新版本。把命令在仓库根目录运行。

```bash
python -m pip install -r requirements.txt
python scripts/export_gif.py atlas.png output/action.gif --duration-ms 2300
```

`atlas.png` 为 **4×4 等分的透明 PNG**。把 16 个连续姿势按从左到右、从上到下排列，每格留出空白边缘。也可以提供 **512×512、16 帧的透明源 GIF**。

| 参数 | 用法 |
| --- | --- |
| `--duration-ms 2300` | 设置整个循环的时长，最少 1600 毫秒，以 10 毫秒为单位 |
| `--size 320` | 设置正方形输出边长，范围 128 至 1024 像素 |
| `--background "#f8f5fc"` | 使用指定的实底颜色，省略时输出透明底 |
| `--order` | 用逗号分隔的 16 个索引调整关键姿势顺序，索引从 0 到 15 |

### 导出小红书九宫格 MP4

需要支持 H.264 编码的 FFmpeg 和可显示标签文字的字体。默认字体为 Linux 上的 Noto Sans CJK。若字体在别处，用 `--regular-font` 和 `--bold-font` 传入字体文件。

在仓库根目录新建 `showcase.json`，将示例路径换成实际 GIF 路径。顺序为左到右、上到下。路径相对清单文件，`seconds` 可设为 1 至 60 秒。

```json
{
  "title": "角色招牌动作",
  "subtitle": "9 张循环动图",
  "seconds": 8,
  "items": [
    {"name": "角色一", "gif": "output/01.gif"},
    {"name": "角色二", "gif": "output/02.gif"},
    {"name": "角色三", "gif": "output/03.gif"},
    {"name": "角色四", "gif": "output/04.gif"},
    {"name": "角色五", "gif": "output/05.gif"},
    {"name": "角色六", "gif": "output/06.gif"},
    {"name": "角色七", "gif": "output/07.gif"},
    {"name": "角色八", "gif": "output/08.gif"},
    {"name": "角色九", "gif": "output/09.gif"}
  ]
}
```

```bash
python scripts/showcase.py showcase.json output/showcase.mp4
```

视频把浅色背景合成到画面里，九格各按自己的 GIF 时间轴循环。**每组默认生成 9 张独立 GIF + 1 个九宫格 MP4，并将两类成品放进同一个 ZIP；不再用封面或主题占第九格。** 如需发布文案，同时附可直接复制的小红书标题、正文和话题标签。

## 仓库文件

- [SKILL.md](SKILL.md) 定义从输入到交付的制作流程。
- [scripts/export_gif.py](scripts/export_gif.py) 处理关键姿势、导出并校验 GIF。
- [scripts/motion.py](scripts/motion.py) 估算相邻姿势的运动，用于生成过渡画面。

## 默认商品交付：独立 GIF + 2×4 / 3×3 MP4 + ZIP

为小红书卖货，每次批量创作 GIF 时，默认**额外制作一个浅色实底、多宫格同屏播放的竖版 MP4**，而且 ZIP 同时包含全部独立 GIF 与展示 MP4。8 张对应 **2×4**，9 张对应 **3×3**，不复制角色来凑九格。视频默认 **1080×1920、9:16、60 FPS、H.264、8 秒**；独立 GIF 默认不加字，展示 MP4 可添加角色标签及定制引导。逐格按源 GIF 节奏循环。发布前检查流畅度、是否黑底、是否裁切及文件能否播放。64 帧若来自关键帧插值应核对重影，不宣称是 64 张原生绘画。

对于 8 张 GIF，`showcase.json` 的 `items` 放 8 条；对于 9 张则放 9 条。运行：

```bash
python scripts/showcase.py showcase.json output/showcase.mp4
```

商品包应包含：每张独立 GIF、多宫格 MP4、简短使用说明。发布时优先用 MP4 吸引浏览，再根据客户需求单独发送 GIF。


## 用户最新确认的交付优先级（覆盖此前默认数量）

**默认先制作九张彼此独立、可单独出售或发送的 GIF；九张全部完成后，再将这九张原始 GIF 作为素材，制作一个 3×3 九宫格动态展示 MP4；最后把九张独立 GIF 和一条 MP4 放进 ZIP。** GIF 是商品主体，MP4 仅用于小红书同屏预览，不能替代九张 GIF。用户明确指定其他数量时遵从用户指定，但不擅自把默认九张改为八张。推荐先逐张验收，再做 MP4，避免预览片与独立 GIF 不一致。
